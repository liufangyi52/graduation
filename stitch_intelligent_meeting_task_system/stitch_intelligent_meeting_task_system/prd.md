## 1. 项目背景与产品定位

### 1.1 业务背景

在项目团队日常运转中，会议纪要依赖人工整理、会议决议与待办任务依靠手动拆解登记，存在任务遗漏、权责不清等问题；项目进度线下跟踪，进度状态、延期风险发现滞后，项目追溯与复盘缺少有效数据支撑。

传统项目管理系统缺少智能化能力，无法联动会议内容自动生成任务，人力成本高、流程效率低。本系统结合大模型、智能体、检索增强技术，打造智能化项目管理平台，打通「会议纪要 — 任务拆解 — 进度跟踪 — 风险预警 — 审计追溯」全链路。

### 1.2 技术背景

项目以 Vue 3、NestJS、MySQL、Redis 与 BullMQ 为技术底座，构建前后端一体化的项目管理业务系统，融合大模型、智能体编排与 RAG 检索增强能力。系统采用分层适配架构，建立独立的 LLM 适配层，默认接入 DeepSeek 大模型，并兼容 Qwen 作为备选方案；检索模块默认采用 BGE-M3 进行文本向量化、BGE Reranker 进行检索结果重排，并默认对接 Qdrant 向量数据库。架构预留第三方办公平台接入接口，向量数据库、大语言模型和 AI 流程组件均通过标准化接口实现独立替换与扩展，以支持快速迭代和后续多模型、多平台集成。其中 Redis 用于热点数据缓存与任务状态缓存，BullMQ 用于会议纪要解析、向量化入库和 AI 推理等耗时任务的异步调度、失败重试与执行状态追踪。


### 1.3 产品定位

本系统是一款多角色协同的智能化项目管理系统，以会议纪要智能体为核心，实现会议内容解析、智能任务抽取、自动任务分派、项目进度跟踪、延期风险预测与全流程审计追溯。系统兼顾单机自用、多账号协作、外部服务对接测试三大场景，同时满足工程落地与毕业论文实验双重目标。

### 1.4 核心价值

业务价值：减少人工整理纪要、拆解任务的工作量，实现项目进度透明化，提前识别项目延期风险；

技术价值：落地大模型 + 智能体 + RAG 融合方案，实现可解释、可复核、可优化的 AI 业务流程；

实验价值：搭建多对比方案运行环境，支撑大模型业务落地效果的消融实验分析；

扩展价值：模块化分层架构，支持多模型、多第三方平台插件化接入，具备长期迭代能力。


## 2. 目标用户、角色与权限边界 ��

### 2.1 目标用户

核心用户：项目管理人员、项目执行成员；

运维用户：系统管理员；

审计用户：流程审计、数据追溯人员；

### 2.2 角色定义与职责

项目经理：系统核心使用角色，负责会议纪要导入、AI 结果审核、任务分派、项目全局管理、风险处置。

系统管理员：账号管理、全局参数配置、外部服务接口配置、系统数据维护。

审计人员：查看全流程操作日志、AI 执行记录、数据变更记录，负责问题追溯。

### 2.3 角色协作关系

明确各角色间数据流转、业务交互规则：项目经理产出任务 → 项目成员执行并反馈进度 → 系统自动统计进度与风险 → 管理员维护系统配置 → 审计人员全程追溯操作记录。

### 2.4 精细化权限边界

功能权限：按角色划分 AI 操作、审核、编辑、查看、配置等功能入口；

数据权限：不同项目、会议、任务数据按账号隔离，越权访问拦截；

操作权限：区分普通编辑、批量操作、数据回滚、日志导出等高权限动作。

### 2.5 扩展预留 ��

预留第三方身份登录系统对接接口，仅做接口框架与模拟逻辑，用于对接测试。

## 4. 核心业务流程：会议纪要导入至任务闭环 ����

### 4.1 主业务全流程（多角色协同）✅

会议纪要导入 → 版本管理 + 数据隐私脱敏 → AI 智能处理（摘要 / 决议 / 任务抽取 / 延期风险预测）→ 项目经理人工复核（通过 / 驳回）→ 正式任务自动分派 → 项目成员更新进度 + 提交工作反馈 → 系统进度统计 + 延期风险预警 → 全链路日志记录。

### 4.2 异常与数据回退流程 ✅

AI 抽取错误 / 任务配置异常 / 内容修改失误 → 人工发起版本回滚 → 系统恢复历史数据 → 重新执行 AI 解析或人工编辑 → 全流程记录回滚操作日志。

### 4.3 AI 多模式执行流程（消融实验专用）��

系统支持模式一键切换：无 AI 纯人工流程 → 单轮大模型流程 → RAG 检索增强流程 → 智能体编排流程，四种流程独立运行，用于对比实验。

### 4.4 外部服务调用流程 ��

业务触发 AI / 向量库调用 → 适配层判断运行模式 → 模拟模式返回构造数据 / 真实模式调用外部接口 → 数据回传系统解析展示。

## A. 页面信息架构与页面规格

前端采用桌面优先的后台系统布局：左侧主导航、顶部项目/用户上下文、内容区。默认适配 1280px 及以上宽度，1024px 时侧栏折叠；不单独建设移动端管理界面。登录后按角色加载可见菜单，未授权路由跳转至 403 页面。

所有列表页统一提供：关键词搜索、常用条件筛选、分页、排序、刷新；首次加载显示骨架屏，空数据提供创建/导入入口，接口异常展示可重试提示。删除、归档、回滚、批量通过等不可逆或影响范围较大的操作必须二次确认，并显示影响对象数量。

|   |   |   |   |
|---|---|---|---|
|**优先级**|**路由 / 页面**|**主要用户**|**展示与关键交互**|
|P0|/login 登录|全部|账号密码登录；登录失败提示；按角色进入对应首页。|
|P0|/dashboard 工作台|项目经理 / 成员|经理看全部项目指标、待审核、风险和即将到期任务；成员看我的待办、反馈和通知。|

|P0|/projects/:id 项目详情|项目成员|概览、任务、会议、风险、成员五个 Tab；顶部显示项目状态、完成率、成员数与快捷操作。|
|P0|/projects/:id/meetings 会议列表|项目成员|会议时间、标题、纪要版本、AI 状态、审核状态；导入纪要并进入详情。|

## B. 核心实体字段与前端表单规则

表单中“必填”字段必须在提交前校验；日期采用 yyyy-MM-dd，时间采用 yyyy-MM-dd HH:mm。标识类字段由后端生成，不在创建表单中编辑。列表默认按最近更新时间倒序排列。

|   |   |   |
|---|---|---|
|**实体**|**前端必须维护 / 展示字段**|**创建或编辑规则**|
|项目|名称*、编码、描述、负责人*、计划开始日、计划结束日、状态、标签、成员、完成率|名称 2-50 字；负责人必须为项目成员；归档后禁止新增会议和任务。|
|会议与纪要|项目*、会议标题*、会议时间*、参会人、来源类型、原文*、版本号、脱敏状态、AI 状态、审核状态|支持粘贴文本、TXT、DOCX；导入前预览；同项目同标题同时间提示重复。|
|AI 解析记录|运行模式、任务状态、摘要、决议、候选任务数、置信度、来源证据、错误信息、开始/结束时间|仅展示，不允许直接改写原始运行记录；重新解析会新建一条记录。|
|候选任务|标题*、描述、负责人建议、计划开始/截止日、优先级、预估工时、风险等级、置信度、原文证据、审核状态、驳回原因|审核前允许经理编辑；通过后生成正式任务并保留与 AI 记录的关联。|
|正式任务|标题*、描述、所属项目*、负责人*、计划开始日、截止日*、优先级*、进度%、状态、预估/实际工时、风险等级、来源会议、备注|进度范围 0-100；完成状态必须填写实际完成时间；成员仅编辑本人任务的进度、状态、反馈和备注。|
|任务反馈|任务*、反馈内容*、进度%、问题类型、附件预留、提交人、提交时间|提交反馈后写入任务动态；进度小于原进度时需填写原因。|
|风险|关联任务、风险等级、触发原因、建议措施、处理状态、处理人、处理说明|系统规则或 AI 生成；经理可调整等级并标记已处理。|
|通知|类型、标题、内容、关联对象、已读状态、创建时间|只读；点击后标记已读并跳转到项目、任务或审核页面。|

统一枚举：项目状态为“进行中、已暂停、已归档”；任务优先级为“低、中、高、紧急”；任务状态为“待处理、进行中、已完成、已关闭”；风险等级为“低、中、高”；AI 运行模式为“无 AI、单轮大模型、RAG 检索增强、智能体编排”。

## C. 状态机与关键交互约束

状态改变必须记录操作人、操作时间、变更前后值与原因（适用时）。页面只展示当前角色允许执行的下一步操作，不提供跳跃式状态修改。

|   |   |   |
|---|---|---|
|**对象**|**状态流转**|**前端约束**|
|项目|进行中 <-> 已暂停 -> 已归档|归档需二次确认；已归档项目只读，可恢复为进行中。|
|纪要版本|草稿 -> 已导入 -> 已脱敏 -> 已提交解析|修改原文后生成新版本；历史版本只读，可查看差异并回退。|
|AI 解析任务|排队中 -> 处理中 -> 成功 / 部分成功 / 失败 / 超时|处理中禁止重复提交；失败/超时显示原因与“重试”按钮；重新解析产生新运行记录。|
|候选任务|待审核 -> 已通过 -> 已生成正式任务；待审核 -> 已驳回 -> 待重新解析|批量通过前显示选中数量；已生成正式任务后不可再次通过；驳回原因必填。|
|正式任务|待处理 -> 进行中 -> 已完成 -> 已关闭|成员可将待处理改为进行中；完成时进度自动校验为 100%；关闭仅项目经理可执行。|
|风险|待处理 -> 跟进中 -> 已处理|已处理需填写处理说明；关联任务重新逾期时生成新的风险记录。|

审核页的固定操作顺序：选择 AI 运行记录 -> 核对原文证据 -> 编辑候选结果（可选）-> 单条或批量通过/驳回 -> 系统生成正式任务和通知 -> 回到项目任务 Tab 查看结果。候选任务与正式任务必须在界面上明确区分，避免用户误以为审核前任务已生效。

|---|---|---|---|---|

|项目与成员|管理（所属项目）|查看成员|管理全部|查看|

|任务反馈|查看/补充|本人|查看|查看|

## E. 看板、图表与前端数据口径

图表必须同时展示数据范围与刷新时间；无数据时展示说明，不绘制误导性的零值图。所有指标支持按项目和日期范围筛选，项目成员默认仅看到本人数据。

|   |   |   |
|---|---|---|
|**视图**|**数据与计算口径**|**交互要求**|
|项目总览|项目完成率 = 已完成任务数 / 未关闭任务总数；待审核数、进行中任务数、逾期任务数、高风险任务数。|点击指标卡跳转至带对应筛选条件的任务、审核或风险列表。|
|甘特图|使用正式任务的计划开始日、截止日、状态和负责人；未填开始日时以创建日作为临时开始日并标识。|支持按负责人/状态筛选，点击条目进入任务详情；今天线、逾期任务和已完成任务需要视觉区分。|
|任务完成趋势|按日统计完成任务数与累计完成率。当前 PRD 未定义迭代与工作量，因此 MVP 不实现严格燃尽图。|支持近 7 天、近 30 天和自定义日期；后续引入迭代和预估工时后可升级为燃尽图。|
|风险分布|按低/中/高风险等级统计；逾期任务自动至少为中风险，截止日临近规则由系统配置确定。|点击扇区或柱状项跳转风险中心并带等级筛选。|
|AI 实验对比|按运行模式统计处理耗时、抽取准确率、人工修正率、成功率。准确率需基于人工标注的候选任务/决议结果计算。|以模式为对比维度；显示样本量和日期范围，样本量不足时提示结果仅供参考。|

前端联调最低数据约定：列表接口返回 items、total、page、pageSize；详情接口返回实体、关联统计与权限标记；所有写操作返回最新实体或任务 ID；异常至少区分参数校验失败、无权限、资源不存在、状态冲突、外部 AI 服务失败和系统异常。

## F. 前端启动顺序

第一阶段（P0）：登录与布局、工作台、项目/成员、会议导入、AI 复核、任务列表与我的任务、风险中心。

第二阶段（P1）：通知、审计日志、实验中心、系统配置、导出与完善图表。

页面开发前先确认：任务字段与状态枚举、权限接口返回方式、会议原文证据定位的数据结构、AI 异步任务轮询或推送机制。
