# MeetingFlow 生产化改造设计

## 目标

将当前演示型 MeetingFlow 改造成可本地部署、可复现验收的会议纪要智能体系统。系统必须使用真实 DeepSeek 或 OpenAI 模型，在人工复核后把可追溯的会议分析结果写入项目任务与风险数据，并支持进度分析、导出、失败回退和消融实验。

## 范围与交付批次

本次改造分四个可独立验收的批次实施：

1. 工程恢复与核心闭环：恢复 monorepo 的 `apps/web`、`apps/api`、`apps/ai`、Docker 和文档；使用 MySQL 保存账户、项目、会议、分析、任务、风险与审核记录；接入真实模型并保留人工审核关卡。
2. 可靠性与数据治理：引入 Redis 缓存和 BullMQ 分析队列，支持失败重试、超时、死信和人工重新发起；实现文本脱敏、审计、索引、数据导出和角色权限。
3. RAG 与可扩展智能体：实现模型供应商、向量存储和工具调用的接口层；使用 Qdrant 检索项目计划、历史纪要和任务反馈；将脱敏、检索、结构化抽取、规则校验和人工审核作为可追踪步骤。
4. 实验与论文支撑：保存标注样本、运行配置、模型输出、人工修正和指标；比较无 AI、单轮 LLM、RAG、智能体编排四种策略，并生成可导出的实验数据。

每一个批次均提供 API 文档、前后端联调说明、异常情形及权限规则，不以静态页面或硬编码指标替代服务端能力。

## 架构

`apps/web` 为 Vue 3 前端，只显示来自 API 的业务数据并提交用户操作。`apps/api` 为 NestJS 业务服务，负责 JWT/RBAC、MySQL 持久化、Redis 缓存、BullMQ 队列、审计、导出以及 API 输入校验。`apps/ai` 为 FastAPI 智能服务，通过提供商适配器调用 DeepSeek 或 OpenAI，并通过向量存储适配器检索知识片段。

所有跨服务数据必须包含关联 ID：`meeting_id`、`analysis_id`、`run_id` 和 `trace_id`。AI 输出一律是待审核草稿，只有项目经理批准后才生成正式任务、分派通知和风险记录。

## AI 流程

1. API 接收会议原文、项目和参会者，并记录不可变的会议版本。
2. 后台任务执行隐私过滤，保存脱敏映射的摘要而非原始敏感值。
3. RAG 层按照项目 ID 检索项目计划、历史纪要、开放任务和成员反馈；每条结果包含来源、片段、相似度和版本。
4. 提供商适配器请求指定模型输出 JSON：摘要、决议、候选任务、分派建议、延期风险、置信度与原文证据位置。
5. 规则引擎校验负责人是否是项目成员、截止日期是否合法、任务标题是否重复、风险等级是否符合逾期规则。
6. 保存步骤级 trace、提示词版本、模型名、耗时、错误与引用证据，状态转为 `pending_review`。
7. 项目经理可编辑、批准或驳回候选项。批准操作以事务写入正式任务、风险、通知和审核日志。

模型请求失败时，任务进入 `retrying` 或 `failed` 状态；最多重试三次。管理员或项目经理可使用原始会议版本重新发起。任何失败都不会创建正式任务。

## 数据与治理

MySQL 存储业务事实与审核历史。表需为常用筛选增加复合索引：项目/创建时间、任务负责人/状态/截止日、会议项目/时间、分析状态/创建时间、审计对象/时间。Redis 仅缓存可重建的仪表盘与列表查询，并使用明确的失效键；队列状态以 MySQL 记录为准。

原文在模型调用前执行手机号、邮箱、身份证号等规则脱敏。系统保存规则版本、替换数量和审核人；导出数据按照角色过滤，审计日志不可被普通业务接口修改。样本集使用项目、时间范围和随机种子抽样，以确保实验可复现。

## API 与权限

- 成员：查看获授权项目，更新本人任务与反馈，查看与本人相关的通知和风险。
- 项目经理：管理所属项目，导入会议，发起/重试分析，编辑、批准或驳回候选结果，管理任务和风险，导出所属项目数据。
- 管理员：管理用户、提供商配置、脱敏规则、指标模板和全局运行记录。
- 审计员：只读访问审核日志、AI trace、实验记录和导出记录。

所有写入 API 返回最新实体或异步任务 ID；错误统一区分字段校验、未授权、资源不存在、状态冲突、外部模型失败和内部错误。分页列表统一返回 `items`、`total`、`page`、`pageSize`。

## 可视化、导出与实验

仪表盘、甘特图、趋势图、风险分布和燃尽/完成趋势均由服务端聚合真实数据。导出至少支持 CSV，按角色和项目范围生成；导出动作记录审计日志。

实验中心使用冻结的标注样本，记录模式、模型、提示词版本、检索配置、运行时间、样本量、准确率、召回率、人工修正率、端到端耗时、成功率与估算成本。无 AI 模式使用人工标注基线；单轮 LLM 禁用检索；RAG 启用检索；智能体编排启用检索及规则校验。结果可导出 CSV，供论文作图和统计分析。

## 测试与验收

每个业务规则和适配器都先编写单元测试；API 以集成测试覆盖权限、审核事务、任务重试和数据隔离；端到端测试覆盖“会议输入 -> 真模型分析 -> 人工审核 -> 入库 -> 指标 -> 导出/失败重试”。真实模型测试使用独立标记，默认单元测试不消耗密钥。

验收时以 Docker Compose 启动 MySQL、Redis、Qdrant、API、AI 服务和前端；使用真实模型密钥完成至少一条完整闭环，并演示一次模型失败后的重试或重新发起。

## 决策与约束

- 正式代码以恢复后的根目录 monorepo 为准；当前嵌套原型仅作为迁移参考，必须先保留且不覆盖。
- 模型供应商首选 DeepSeek，OpenAI 通过同一适配器配置启用。
- AI 永远不能绕过人工复核直接落正式任务。
- 不在本期实现多租户计费、实时语音转写、IM 或完整 OA 审批。
