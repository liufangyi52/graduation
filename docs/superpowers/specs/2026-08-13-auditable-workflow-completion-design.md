# 可审计协作闭环补强设计

## 目标

在不改变四类角色职责边界的前提下，补齐当前项目的审计检索与安全关联摘要，并将会议版本恢复、重新分析和任务风险通知完善为可验收的业务闭环。

## 范围

本次交付包含四项能力：

1. 审计日志按时间范围、操作者、项目、对象类型和操作类型筛选。
2. 审计日志提供不跳转业务页面的只读关联摘要。
3. 项目经理可恢复会议历史版本，并保留版本及分析历史。
4. 任务分派、临近截止和逾期通知覆盖任务负责人和项目经理，并对未读提醒去重。

不包含审计人员的业务详情访问、原始会议内容或反馈正文展示、审计日志编辑/删除、审计日志导出、通用消息推送渠道、定时扫描器，以及管理员对项目业务数据的写操作。

## 角色与权限

- 项目经理：管理本人项目的会议版本和重新分析；接收本人项目任务的临近截止与逾期提醒；可读取审计日志。
- 项目成员：接收本人任务的分派、临近截止与逾期提醒；不管理版本、不重新分析、不读取审计日志。
- 系统管理员：读取和筛选审计日志；管理账号和系统设置；不执行项目业务写操作。
- 审计人员：只读读取和筛选审计日志及个人通知；仅查看审计关联摘要，不获得项目、会议、任务、风险或 AI 审核页面访问权。

## 审计日志

### 查询接口

扩展 `GET /api/audit-logs`，接受可选查询参数：

- `from`、`to`：ISO 日期 `YYYY-MM-DD`，分别表示含当天起止边界。
- `actorId`：操作者用户 ID。
- `projectId`：来自日志 `details.projectId` 的项目 ID。
- `entityType`：日志对象类型。
- `action`：完整操作名称，如 `task.updated`。

接口仅允许管理员和审计人员调用。无参数时保持现有倒序、最多 500 条的行为。所有参数使用参数化查询；无效日期、未知筛选值或 `from` 晚于 `to` 返回 `400`。

响应中的每条日志包含既有字段，以及 `summary`：

```ts
type AuditLogSummary = {
  projectId: string | null
  projectName: string | null
  entityLabel: string | null
  changedFields: string[]
}
```

`projectId` 从日志详情中的 `projectId` 取得；若日志对象是项目且未包含该字段，则使用 `entityId`。`projectName` 和 `entityLabel` 只从服务端按 ID 查询名称，且仅针对项目、任务、会议、分析、风险、用户与会议版本等已知类型。查询不到时返回 `null`，不影响该日志显示。

`changedFields` 只从 `details.fields`、安全的键名集合或明确记录的状态/进度字段生成。不得返回会议原文、任务描述、反馈正文、密码、令牌、脱敏规则正则或外部服务配置值。

### 审计界面

`/audit-logs` 增加筛选栏、重置操作、匹配数和每行“查看摘要”操作。摘要以模态框或展开面板展示：操作者、时间、操作、对象类型/ID、项目名、关联对象名称和变更字段。审计人员点击该操作不得导航到业务页面。

## 会议版本与重新分析

会议版本恢复仅允许该项目经理执行。恢复历史版本时，系统读取目标版本，创建新的 `meeting_versions` 记录，`source_type='restore'`，设置为当前版本，并写入 `meeting.version_restored` 审计日志。旧版本不更新或删除。

重新分析仅允许该项目经理执行。系统保留原 `ai_analyses` 记录，创建一条与原记录关联的新分析记录；新记录进入待审核状态。重新分析和后续审核分别写入审计日志。成员、管理员和审计人员均不能执行这两项写操作。

会议页面和审核页面均展示版本来源、创建时间和可追溯的重新分析来源；恢复和重新分析前显示确认操作。仅项目经理显示对应入口。

## 通知与风险提醒

任务创建或改派时，向新的任务负责人创建分派通知。未完成且未关闭任务在被更新、提交反馈或被管理编辑时，若截止日在三天内或已逾期，系统创建或保留风险记录，并通知：

- 任务负责人；
- 任务所属项目的负责人。

对于同一任务、同一提醒类型（临近截止或逾期）、同一接收者，只允许存在一条未读通知。任务完成或关闭后不创建新的截止提醒。风险记录同样按项目和风险标题去重。

通知内容不得暴露会议原文、反馈正文或系统配置。链接遵守接收者权限：成员链接至 `/my-tasks`，项目经理链接至可访问的项目任务视图或风险视图。

## 错误处理

- 无权角色调用受限接口或执行恢复/重新分析，返回 `403`，且不得产生数据库写入或通知。
- 版本、分析、项目、任务或筛选关联对象不存在，返回 `400` 或将对应摘要字段置空，具体以是否为命令型请求区分。
- 任何写操作失败时，事务内的版本、当前版本指针、分析记录、风险和通知均回滚；审计日志仅在成功完成业务写入后写入。

## 验收与测试

1. 管理员和审计人员可按全部五类条件筛选日志；项目成员和项目经理读取日志返回 `403`。
2. 审计摘要显示安全字段，并不含会议原文、任务描述、反馈正文、密码或配置值；审计人员前端没有业务详情跳转。
3. 项目经理恢复会议版本后产生新的恢复版本且旧版本仍存在；其他角色不能恢复。
4. 项目经理重新分析后保留原记录并得到新的待审核记录；其他角色不能重新分析。
5. 创建或改派任务时通知新负责人；临近截止和逾期时通知负责人和项目经理；重复检查不产生重复未读通知；完成或关闭任务不产生新的截止通知。
6. 执行完整 `npm test` 与 `npm run build` 成功。
