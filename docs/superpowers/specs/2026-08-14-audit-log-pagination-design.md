# 审计日志分页表格设计

## 目标

为审计人员在 `/audit-logs` 页面提供清晰、可滚动的关键操作记录表。表格维持既有字段“时间、操作者、操作、对象、详情”，首屏固定展示 15 条记录；当记录总数超过当前每页条数时显示完整的原生分页组件。

## 范围

- 仅调整 Vue 客户端的审计日志视图和相关样式，不修改 `GET /audit-logs` 接口、数据库结构或审计记录字段。
- 继续使用现有真实审计日志数据源。页面总数取接口返回条数，分页在客户端切片处理。
- 页面继续由现有角色权限保护；右上角用户区域依据当前会话显示“审计人员”。
- 不增加筛选弹窗、详情弹窗、批量操作、导出或字段变更。

## 页面结构

1. 保持现有左侧固定导航及“审计日志”高亮状态，右侧页头显示“审计日志”和“查看关键操作和数据变更记录”。
2. 主内容为“关键操作记录”面板，浅色表头与明确分割线符合现有浅白、淡蓝企业后台样式。
3. 表格列顺序固定为：时间、操作者、操作、对象、详情。详情单元格显示单行、截断后的 JSON 字符串，悬停可通过原生 `title` 查看完整原文。
4. 表格滚动容器设定稳定高度，纵向滚动时表头保持可见；窄视口保留横向滚动能力，避免压缩字段内容。

## 分页行为

- 初始页码为 1，初始每页条数为 15。页面记录按接口返回顺序呈现。
- 当前页渲染 `auditLogs.slice(start, end)`，保证第一页至多显示 15 条。
- 分页区在总条数大于当前每页条数时显示，并包含总条数、上一页/下一页、可见页码按钮、页码跳转数字输入、每页条数选择器。
- 上一页和下一页在边界禁用。跳转值限制在有效页码范围内。
- 切换每页条数时回到第一页；日志刷新后若当前页越界，收敛到最后一个有效页。
- 当日志为空时仅显示既有空状态，不显示分页区。

## 测试与验收

- UI 测试覆盖分页派生状态：默认页大小为 15、首屏只取前 15 条、总数和总页数正确、页码切换可访问对应记录、切换每页条数重置页码。
- 运行相关 Vitest 测试与生产构建。
- 以桌面视口检查审计人员身份文案、左侧选中菜单、五列表头、15 行首屏数据、固定表头和完整分页控件；以窄视口确认表格横向滚动而不发生文本重叠。
