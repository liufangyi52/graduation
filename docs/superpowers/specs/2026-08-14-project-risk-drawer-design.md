# 项目分析风险任务抽屉设计

## 目标

在项目分析页的风险分布卡片中，让用户点击中风险或高风险的环形图色块后，在当前页面查看对应的开放风险任务。该交互不跳转路由、不调用新接口，也不修改风险数据。

## 范围

- 保留现有统计卡片、任务完成趋势、甘特图、风险环形图和图例。
- 将风险环形图改为可分别响应中风险和高风险点击的 SVG 环形图；低风险部分保持展示但不可打开抽屉。
- 中风险和高风险图例项也作为相同交互的键盘可访问入口。
- 抽屉显示选中等级的标题和任务名称列表，仅展示 `status === 'open'` 的风险。
- 点击关闭按钮或轻蒙层空白区域关闭抽屉。

## 数据与状态

组件新增 `selectedRiskLevel`，取值为 `medium`、`high` 或 `null`。当它为中风险或高风险时，使用当前 `detail.risks` 计算出等级匹配且状态为开放的列表；为 `null` 时不渲染蒙层与抽屉。

不引入模拟任务、持久化状态或服务端改动。抽屉标题通过既有 `riskLevelLabel()` 生成，例如“中风险任务”和“高风险任务”。

## 界面与交互

抽屉固定在视口右侧，宽约 340px，具有白色背景、细边框和轻阴影；蒙层使用低不透明度颜色，保证项目分析页面仍清晰可见。抽屉顶部包含动态标题和带无障碍标签的关闭按钮，主体为简洁任务列表。

SVG 中的中风险黄色区块与高风险红色区块各自具有按钮语义、焦点态和点击处理。图例中的中、高风险行使用相同的打开处理，支持鼠标、触摸和键盘操作。点击蒙层自身关闭，点击抽屉内部不关闭。

## 边界情况

若某等级没有开放风险，抽屉仍显示该等级标题，并显示“暂无开放风险任务”。关闭风险不在列表中出现。低风险色块与图例保持信息展示，不打开抽屉。

## 验收与测试

在项目分析 UI 测试中先断言风险抽屉状态、可点击的中高风险入口、动态标题、任务筛选、空列表文案和关闭行为的源代码契约；新增断言必须在实现前失败。实现后运行该测试文件、完整 `npm test` 和 `npm run build`。
