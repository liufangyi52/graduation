# 审计人员职责隔离设计

## 目标

将审计人员从项目业务工作流中隔离出来，使其只能在审计工作台查看审计所需的只读信息，不能访问或执行项目经理职责。

## 角色边界

审计人员仅可访问以下页面：

- 审计工作台（`/dashboard`）：展示审计概览、最近关键操作和数据变更摘要。
- 审计日志（`/audit-logs`）：查看全量操作日志及其关联对象和详情。
- 通知中心（`/notifications`）：查看并处理自己的站内通知。

审计人员不得访问项目、任务、风险、会议纪要、AI 审核、实验中心、日历、效能分析、账号管理和系统设置页面。项目详情及其子路由同样不在审计角色的可访问范围内。

## 前端设计

`authService` 的角色路由白名单将审计人员收紧为 `['/dashboard', '/notifications', '/audit-logs']`。应用导航和路由守卫均使用该白名单；审计人员手工输入被禁止的 URL 时，应用重定向到仪表盘。

`App.vue` 为审计人员提供专属仪表盘。该页面不复用项目经理的项目、任务或风险管理组件，也不包含任何创建、编辑、分派、审核或处置入口。页面数据只来自审计日志和现有只读通知。

## 服务端授权

保留审计日志查询给管理员和审计人员。审计人员不得读取项目、项目详情、任务、风险、会议、AI 分析、日历或项目成员等业务资源；相应查询在服务层明确拒绝审计人员，而非依赖前端隐藏菜单。

既有项目经理写操作继续要求 `manager` 角色与项目归属校验。管理员的系统管理职责保持不变。

## 错误处理

被禁止的前端路径重定向至审计工作台，避免空白页。被禁止的 API 请求返回现有 `ForbiddenException`（HTTP 403），且不得执行数据库写入或返回业务数据。

## 测试

新增或扩展测试验证：

- 审计人员的可见路由仅为仪表盘、通知和审计日志。
- 审计人员访问业务路由会被前端守卫重定向。
- 审计人员对项目、任务、风险及会议相关查询被服务端拒绝。
- 审计人员仍可读取审计日志；项目经理与管理员的既有权限不回归。
