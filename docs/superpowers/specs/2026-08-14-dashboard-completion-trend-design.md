# 首页任务完成趋势设计

## 目标

让工作台的“任务完成趋势”基于真实任务完成记录展示，并在任务状态变更后随现有刷新机制更新。

## 根因

任务更新会写入 `audit_logs`，项目详情接口已通过该日志推导 `completedAt`。但是首页使用的 `GET /tasks` 查询和客户端 `Task` 类型未传递创建时间或完成时间，且首页趋势区域是固定的空状态。

## 方案

复用审计日志，不新增状态历史表。

1. `GET /tasks` 返回任务的 `created_at` 以及从审计日志推导的首次完成时间 `completed_at`。
2. 客户端 `Task` 类型和映射保留 `createdAt`、`completedAt`。
3. 首页将全部可见任务传给既有 `buildProjectAnalytics`，按完成日期聚合出趋势点。
4. 有趋势点时显示日期、完成数量和相对高度的柱状图；没有可信完成时间时保留说明性空状态。
5. 任务保存后立即调用既有 `service.load()`；其他页面继续按 10 秒间隔刷新，因此无需引入 WebSocket 或轮询之外的机制。

## 行为边界

- 仅统计当前状态为 `completed` 且具备可验证完成时间的任务，避免把缺失历史的记录伪造成趋势。
- 沿用项目详情的“首次达到完成状态”规则，保证首页和项目详情的统计口径一致。
- 按当前用户可见的任务范围统计，维持角色权限边界。

## 验证

- 服务层测试确认任务列表 SQL 返回完成时间。
- 客户端测试确认首页任务映射保留完成时间。
- UI 测试确认存在真实完成记录时渲染趋势，缺少记录时显示空状态。
- 运行相关 Vitest 测试及生产构建。
