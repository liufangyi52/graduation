# DeepSeek V4 可用设置设计

## 目标

将系统设置从仅保存展示值改为真实可执行配置：仅使用官方 DeepSeek API 的 `deepseek-v4-pro` 模型，并使系统默认分析模式成为新建会议的默认执行方式。

## 模型配置

- 设置页只显示“DeepSeek V4 Pro”，其保存值和后端调用值均为 `deepseek-v4-pro`。
- 官方 OpenAI 兼容地址继续使用 `https://api.deepseek.com`，密钥继续从 `DEEPSEEK_API_KEY` 读取。
- `.env.example` 的 `DEEPSEEK_MODEL` 默认值改为 `deepseek-v4-pro`。本地 `.env` 的实际密钥不写入代码、测试或日志。
- 后端每次分析从系统设置读取当前模型，并将实际模型标识写入分析记录和执行元数据。

## 运行模式

- 系统设置保存规范模式值：`manual`、`llm`、`rag`、`agent`，界面显示中文名称。
- 新建会议表单在加载设置后使用系统默认模式；用户仍可在会议表单中临时改选，作为单次执行覆盖。
- 服务端在分析请求未携带模式时使用系统设置默认值，确保 API 调用也具备可用默认行为。
- `manual` 不调用模型；`llm` 进行单次 DeepSeek 抽取；`rag` 优先知识库检索，未配置时沿用现有普通 DeepSeek 降级分析；`agent` 使用规划后抽取。

## 兼容与验证

- 兼容已存储的旧模型名称和中文/历史模式值，读取时归一化为 V4 Pro 与规范模式。
- 不修改 DeepSeek API Key、数据库表结构或既有会议数据。
- 测试设置归一化、服务端默认模式与模型传递、前端默认模式同步，并运行定向测试和生产构建。
