# README 项目作品集重构设计

## 目标

将根目录 README 从“项目使用说明”重构为面向招聘者的项目作品集页，同时保留开发者复现项目所需的运行、配置和验证信息。不加入姓名、求职方向、联系方式、个人简历或作品集链接。

## 受众与阅读路径

- 招聘者：在首屏快速理解项目场景、AI 能力和工程亮点。
- 技术面试官：通过架构图、分析模式和功能证据判断实现深度。
- 开发者：在文档后半部分获取本地运行、RAG 配置和测试命令。

阅读顺序为：项目价值 → 可视化证据 → AI 工作流 → 工程能力 → 技术架构 → 运行验证。

## 内容结构

1. 标题与一句话定位：突出“会议纪要智能任务抽取”和“项目进度跟踪”。
2. 项目概览：说明输入、AI 处理、人工审核和跟踪闭环。
3. 项目截图：使用仓库内 `docs/prototypes/` 的真实界面截图，以表格或分组画廊展示仪表盘、会议导入、AI 审核、任务看板、风险中心和分析视图。
4. AI 应用链路：说明脱敏、摘要/决策/任务/风险抽取、审核确认、任务生成和提醒分析。
5. AI 模式：解释 `manual`、`llm`、`rag`、`agent` 的定位，以及 RAG 未配置时的诚实状态标记。
6. 工程亮点：突出结构化输出、RAG 检索、Agent 计划步骤、权限隔离、审计留痕、实时通知和 Redis 降级。
7. 功能与角色：保留项目经理、项目成员、系统管理员、审计人员的职责边界。
8. 技术架构：嵌入 `docs/technical-architecture-diagram.png`，并列出前端、后端、数据库、AI、向量检索和实时通信技术。
9. 本地运行与可选 RAG：保留现有命令和安全提示，适当压缩重复解释。
10. 项目验证与资料：保留测试、类型检查、构建、冒烟测试命令及文档目录说明。

## 图片策略

- 使用仓库内相对路径，确保 GitHub 页面可直接渲染。
- 优先展示产品截图、架构图和测试证据，不新增个人照片或外部图片依赖。
- 图片标题使用功能名称，避免仅用文件名，帮助招聘者建立“能力 → 证据”对应关系。

## 约束与验收标准

- 全文以中文为主，技术名词和命令保留英文。
- 首屏不出现个人身份或联系方式。
- README 不虚构性能指标、模型效果或部署能力；所有亮点应能在代码、截图或测试材料中找到依据。
- 保留 Windows PowerShell 和通用 shell 的运行方式。
- Markdown 链接、图片路径、代码围栏和表格格式正确，文件可被 GitHub 正常渲染。
