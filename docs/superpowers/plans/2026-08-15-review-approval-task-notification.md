# Review Approval Task Notification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Notify the final assignee whenever an approved AI analysis creates a task.

**Architecture:** Keep task creation and notification persistence in `AppService.reviewAnalysis`'s existing transaction. The assignee resolution remains unchanged: an active matching project member for `owner_email`, otherwise the project owner. The notification insert follows each successful task insert, so a notification failure rolls back the review and generated records.

**Tech Stack:** TypeScript, NestJS service layer, MySQL, Vitest.

## Global Constraints

- Do not add an API endpoint or frontend control.
- Reuse the existing `notifications` table and its unread default.
- Send the notification only to the final `assigneeId` and link it to `/my-tasks`.
- Keep manual task reminders and rejected-analysis behavior unchanged.
- Follow TDD: observe the new tests fail before editing production code.
